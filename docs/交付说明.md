## 2. 建设目标与边界

系统面向“当前代码应该测什么、怎样准备、如何判断正确、证据在哪里、知识是否仍然有效”这一问题，
而不是通用文档 RAG。

系统严格区分三类信息：

1. 代码图提供结构、调用与影响范围；
2. 测试知识提供边界、场景、fixture/mock、Oracle、历史缺陷和运行约束；
3. 外部执行结果提供行为是否真实成立的证据。

静态关联不会被冒充为执行验证，模型推断只能形成 `candidate`，人工审核只能提升为 `reviewed`，
只有同仓库、同修订且明确绑定的成功执行证据才能支持 `verified`。

## 3. 已交付架构

```text
代码 / 测试 / 配置 / Git / Issue / CI / 对话 / 执行快照
                         │
                         ▼
                 可替换 Source Adapter
                         │
                         ▼
                  Evidence 证据层
                         │
            ┌────────────┴────────────┐
            ▼                         ▼
    KnowledgeCard 与关系图       ProjectMap 项目地图
            │                         │
            └────────────┬────────────┘
                         ▼
        检索、适用性过滤与 Context Pack 编译
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
       CLI             HTTP/Web          MCP
                                           │
                              Codex / Claude Code / Copilot
```

核心架构选择如下：

- API、CLI、MCP 统一通过 `createDefaultEngine` 组合根装配依赖，避免协议入口各自维护一套逻辑；
- Source Adapter 只产生 Evidence，不直接写最终知识，便于继续增加语言和来源；
- JSONL 保存权威数据，SQLite FTS5 仅作为可重建检索索引；
- 精确符号/路径召回、BM25F 和 CodeGraph 结构上下文互补，结构能力不可用时返回 abstention；
- 知识身份使用显式语义字段投影，新增无关 Schema 字段不会导致整批 ID 漂移；
- 生命周期、冲突、合并、回滚、失效和验证均留下可追溯变更记录；
- 没有适用的 `reviewed` 或 `verified` 知识时，Context Pack 返回 `ordinary_agent`。

## 4. 已交付能力

### 4.1 来源与抽取

- Python/pytest AST 扫描：测试函数、fixture、显式 Factory、mock、断言、期望异常、marker 和参数化；
- Java/JUnit、Go testing、Rust test 的保守静态适配器；
- pytest 配置、依赖、环境文件和带来源的运行指令抽取；
- Git 修复历史、Issue、CI/执行快照、Markdown 和显式对话快照导入；
- 可选 OpenAI-compatible LLM 候选抽取，默认关闭并带内容寻址缓存；
- LLM 输出必须引用已有 Evidence，并经过目标、路径、依赖和代码锚点约束。

### 4.2 知识与治理

- `behavior`、`boundary`、`fixture`、`oracle`、`regression`、`environment` 等知识卡；
- `candidate`、`reviewed`、`verified`、`rejected`、`stale` 生命周期；
- `SUPPORTED_BY`、`COVERS`、`USES_FIXTURE`、`REGRESSION_OF`、`VERIFIES`、
  `VERIFIED_BY`、`INVALIDATED_BY`、`CONFLICTS_WITH`、`MERGED_FROM` 等有类型关系；
- 单卡录入、知识包导入、审核、拒绝、验证、合并、冲突决议和整组回滚；
- Evidence 变化触发关联知识失效，旧记录保留为审计历史；
- EvidenceCluster 与知识卡分别审核，分组确认不会自动确认结论。

### 4.3 Agent 消费

- Context Pack 返回现有测试、fixture/mock、Factory、Oracle、边界、历史回归、运行指令、
  执行信号、项目地图、影响摘要、证据置信度和 abstentions；
- CLI、HTTP、Web 与 MCP 共享同一核心语义；
- 已提供 Codex、Claude Code、Copilot CLI 和 VS Code Copilot 的仓库级 MCP 配置；
- Web 默认只展示当前 14 张 Agent 待审卡，避免与旧 `stale` 身份混淆。

### 4.4 评测治理

- A：普通 Agent；B：Agent + CodeGraph；C：Agent + CodeGraph + TestKnowledge；
- 冻结模型、完整提示、分组工具白名单、预算、任务真值和验收阈值；
- `runSetId`、`runId`、`runSpecHash` 防止跨批次拼接或事后篡改运行条件；
- 被评 Agent 只接收 `agentInput`，私有 `scoring` 仅供隔离评估者使用；
- 分别记录边界、预埋缺陷、有效 Oracle、fixture/mock、无效断言、重复测试、脆弱测试和成本；
- A/B/C 不完整时只能返回 `insufficient_data`。
